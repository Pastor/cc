# cStore

Сервер криптографического файлового хранилища.

Файл шифруется симметричным ключом, симметричный ключ шифруется открытым ключом
владельца и хранится рядом. Закрытый ключ пользователя хранится зашифрованным
ключом, выведенным из его пароля.

## Что сервер знает о ваших файлах

Ничего, кроме размеров и времени операций.

Криптография выполняется **на клиенте**: пароль на сервер не передаётся никогда.
Из него на клиенте выводится мастер-ключ, из мастер-ключа двумя ветвями — ключ
шифрования, который остаётся у клиента, и аутентификационный хеш, который уходит
на сервер вместо пароля. Содержимое, имена файлов и директорий шифруются до
отправки.

Отсюда следуют два свойства, о которых нужно знать заранее:

- **Забытый пароль без ключа восстановления означает безвозвратную потерю
  доступа к файлам.** Сервер не может помочь: ключей у него нет.
- **Веб-клиент доставляется тем же сервером.** Подменённый сервером клиент
  способен похитить пароль. Это ограничение архитектуры, а не недоделка; оно
  смягчается воспроизводимой сборкой и проверкой целостности, но не устраняется.

## Устройство

| Крейт | Ответственность |
| --- | --- |
| `cc-domain` | Сущности предметной области и их инварианты |
| `cc-crypto` | Примитивы: выведение ключей, шифрование, обёртывание |
| `cc-client` | Клиентское ядро: то, что выполняется у пользователя |
| `cc-storage` | Хранение шифротекста и метаданных |
| `cc-api` | Маршруты, представления, спецификация OpenAPI |
| `cc-server` | Тонкий бинарник: конфигурация, наблюдаемость, запуск |

`cc-crypto` и `cc-client` собираются под `wasm32-unknown-unknown`: их использует
и сервер, и веб-интерфейс.

## Требования

- Rust версии, указанной в [rust-toolchain.toml](rust-toolchain.toml). Она
  зафиксирована точным номером, а не каналом: сборка обязана быть
  воспроизводимой.
- Для сборки клиентского ядра под веб — цель `wasm32-unknown-unknown`.

## Сборка и запуск

```bash
cargo build --workspace
```

Конфигурация читается из файла TOML, затем перекрывается переменными окружения с
префиксом `CC_`. Возьмите за основу [cc.example.toml](cc.example.toml):

```bash
cp cc.example.toml cc.toml
CC_CONFIG=cc.toml CC_SECRETS__SERVER=$(openssl rand -hex 32) cargo run --bin cc-server
```

У секретов нет значений по умолчанию: без серверного секрета сервер не
запустится. Это сделано намеренно.

Сервер слушает адрес из `listen`. TLS терминируется **перед** сервером —
обратным прокси или входным контроллером кластера; обоснование в
[TODO.md](TODO.md), раздел 10.2.

## Контейнер

Образ собирается многостадийно: компиляция на образе с зафиксированным
toolchain, запуск — на образе без оболочки, от непривилегированного
пользователя. Корень хранилища и конфигурация приходят извне: предположений о
файловой системе хоста образ не делает.

```bash
docker build --tag cstore:local .
```

Проверка собранного образа — запуск без привилегий, проба готовности и
сохранность тома при перезапуске:

```bash
./scripts/container-smoke.sh cstore:local
```

Готовые образы для `linux/amd64` и `linux/arm64` публикуются из `master` в
`ghcr.io/pastor/cc`. Пример развёртывания — [deploy/kubernetes.yaml](deploy/kubernetes.yaml).

## API

Спецификация OpenAPI публикуется по `/api/openapi.json`, интерактивная
документация — по `/api/docs`.

Версия контракта передаётся заголовком `API-Version`, а не путём: URI
идентифицирует ресурс, а версия относится к его представлению. При отсутствии
заголовка применяется самая новая поддерживаемая версия — если вам нужна
стабильность, присылайте заголовок явно.

Ошибки отдаются в формате `application/problem+json` по RFC 9457.

## Проверки

Изменение не считается готовым, пока не пройдены все ворота:

```bash
cargo check --all-targets
cargo clippy --all-targets --all-features -- -D warnings
cargo fmt --all -- --check
cargo nextest run --all-features --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
./scripts/no-unwrap.sh
```

Те же проверки выполняет конвейер в [.github/workflows](.github/workflows).

## Состояние

Проект переводится на Rust. Прежняя реализация на Kotlin лежит в `web/` как
справочный материал: она содержит рабочую модель предметной области и набор
известных дефектов, которые в новой реализации повторять нельзя. Каждый такой
дефект зафиксирован требованием в [TASKS.md](TASKS.md). Kotlin-код будет удалён
после достижения функционального паритета.
